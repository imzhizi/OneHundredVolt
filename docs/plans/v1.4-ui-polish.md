## 1. 播放列表行显示（播放列表模块，移至此处）

### 1.1 播放列表时长显示统一为分钟格式

**现状差异：**
- iOS：播放列表显示 `item.duration.minutesOnly`，格式为 `XX:XX` 或 `X:XX:XX`
- Android：同上，`toMinutesOnly()` 格式化

**改后行为：**
- 播放列表中，**所有单集**的时长从 "时分秒" 格式改为**总分钟数**（四舍五入到整数）
- 格式：`83 分钟`
- 超过 60 分钟时显示：`83 分钟`（统一用分钟，不转成 "X小时X分"）

### 1.2 当前播放单集显示「还有 XX 分钟」

**现状：**
- 当前播放单集和其他单集在时长显示上没有区分

**改后行为：**
- 当前正在播放的单集，时长位置显示 `还有 83 分钟`（带「还有」前缀）
- 其他单集只显示 `83 分钟`（纯数字+分钟）
- 这个「还有 XX 分钟」是当前播放进度对应的**剩余时间**（= 总时长 - 当前进度），会随播放动态变化
- 显示位置：**播放列表里每个单集的标题下方**，不是全屏播放器

**涉及文件：**
- iOS: `PlaylistRowView` in `HomeView.swift`
- Android: `PlaylistRow` in `HomeScreen.kt`

### 1.3 倍速选项统一

**现状：**
- iOS: `[0.75, 0.85, 1.0, 1.25, 1.5, 2.0]`
- Android: `[0.75f, 0.85f, 1.0f, 1.25f, 1.5f, 2.0f]`

**统一为：**
```kotlin
[0.75, 0.9, 1.0, 1.1, 1.25, 1.5, 2.0]
```

**涉及文件：**
- iOS: `PlayerView.swift` 第 99 行速度列表
- Android: `PlayerScreen.kt` 第 248 行速度列表

### 1.4 Android 下一曲图标与 iOS 对齐

**现状差异：**
- Android MiniPlayerBar 下一曲使用 `Icons.Default.SkipNext`（双箭头+竖线）
- iOS MiniPlayerView 下一曲使用 `forward.fill`（双箭头）

**改后行为：**
- **iOS** MiniPlayerView 的 `forward.fill` → **`"forward.frame.fill"`**（带方框的下一曲图标，形状与 Android `SkipNext` 的「>|」样式对齐）
- **Android** 保持 `Icons.Default.SkipNext` 不变（已是「>|」样式）

**涉及文件：**
- iOS: `MiniPlayerView.swift` 第 74 行
- Android: `MiniPlayerBar.kt` 第 130 行

### 1.5 Android 封面和播放条 padding 调整

**现状：**
- Android `MiniPlayerBar` 水平 padding 12dp，垂直 padding 8dp

**改后行为：**
- 水平 padding `12.dp → 8.dp`
- 垂直 padding `8.dp → 6.dp`

**涉及文件：**
- Android: `MiniPlayerBar.kt`

### 1.6 双端迷你播放器进度条样式对齐

**现状差异：**
- iOS MiniPlayerView 使用 Capsule 进度条，无拖拽圆点
- Android MiniPlayerBar 使用 `LinearProgressIndicator`，Android 默认样式会在右侧显示一个小圆点

**改后行为：**
- Android 改用自定义 `Box` + `Capsule` 绘制，完全对齐 iOS 样式（纯直线，无右侧圆点）

**涉及文件：**
- Android: `MiniPlayerBar.kt`

### 1.7 全屏播放器 Android 快退/快进图标显示时间

**现状：**

**改后行为：**
- 快退按钮：`Icons.Default.Replay` → 自定义图标或文字叠加显示 `15`（与 iOS `gobackward.15` 对齐）

## 8. 可用性

### 8.1 播放进度持久化不丢失

**现状：**
- `PlaybackProgressStore` 通过 `KeyValueStore` 存储进度
- **杀进程重启后播放进度丢失**（进度持久化失效）
- 可能是 `KeyValueStore` 在冷启动时初始化延迟，导致进度被默认值覆盖

**已实现方案（Android）：**

| 事件 | 行为 |
|---|---|
| 播放中每 200ms | 只更新内存，首次更新后触发 15 秒定时落盘 |
| 15 秒定时到 | 同步写磁盘（`commit()`），重置定时器 |
| 用户暂停 | 立即 `flushToDisk()` |
| 快进 / 快退 / 拖动进度条 | 立即 `flushToDisk()` |
| 杀进程（`onTaskRemoved`） | 立即 `flushToDisk()` |
| 切曲 / 播放完成 | `markCompleted()` 触发定时落盘 |

**根因修复：**
- `KeyValueStore.android.kt` 所有写入从 `apply()`（异步）改为 `commit()`（同步），确保 flush 时数据真正落盘
- `PlaybackProgressStore` 新增 `flushToDisk()` 公开方法，取消防抖直接写入

**涉及文件：**
- `shared/src/androidMain/.../KeyValueStore.android.kt` — apply → commit
- `shared/src/commonMain/.../PlaybackProgressStore.kt` — 新增 flushToDisk()，防抖改为 15 秒定时
- `androidApp/.../AudioPlayerManager.kt` — 暂停、seek 时调 flushToDisk()
- `androidApp/.../AudioPlaybackService.kt` — onTaskRemoved 调 flushToDisk()

**涉及文件：**
- shared: `PlaybackProgressStore.kt`
- iOS: `SettingsView.swift`
- Android: `SettingsScreen.kt`

### 8.1.1 音频缓存 Bug 修复 + 断点续传

**现状问题：**
- 下载中途杀进程后，残留 `.tmp` 临时文件
- `cachedFile()` 未排除 `.tmp`，下次播放时把不完整的临时文件传给 ExoPlayer，导致 `FileDataSourceException`，无法播放

**已实现方案（Android）：**

| 场景 | 行为 |
|---|---|
| 首次播放某集 | 用远程 URL 流播，同时后台异步缓存（写 `.tmp`） |
| 下载中途杀进程 | `.tmp` 保留，供下次续传 |
| 再次播放同一集 | `cachedFile()` 只返回正式文件，`.tmp` 不返回；后台续传从断点继续 |
| 服务器支持 Range（206）| 读 `.tmp` 大小，发 `Range: bytes=N-`，追加写入 |
| 服务器不支持 Range（200）| 删掉 `.tmp`，重新下载 |
| 下载完成 | `.tmp` 重命名为正式文件，下次走本地播放 |
| LRU 淘汰超 500MB | `.tmp` 优先淘汰，然后按 LRU 删正式文件 |
| `removeCache()` / `clearCache()` | 连 `.tmp` 一起清掉 |

**涉及文件：**
- `androidApp/.../AudioCacheService.kt` — 断点续传逻辑、LRU 淘汰优先级、cachedFile 过滤 .tmp

### 8.2 退出登录时删除所有进度和缓存

**现状：**
- 退出登录可能只清除 token，残留进度数据和音频缓存

**改后行为：**
- 退出登录时执行以下清理：
  1. 清除 `PlaybackProgressStore` 所有数据
  2. 清除 `DatabaseService` 所有本地 JSON 数据
  3. 清除音频缓存文件（`AudioCacheService` / `SimpleCache`）
  4. 清除 `KeyValueStore` 所有设置
  5. 清除 `SecureStorage` 中的 token
  6. 重置播放列表和播放器状态

**涉及文件：**
- iOS: `SettingsView.swift` didLogout 处理
- Android: `SettingsScreen.kt` logout 处理
- shared: 需要暴露批量清除接口
