## 一、整体策略

**Kotlin Multiplatform (KMP) Monorepo**：iOS 保持 SwiftUI 不动，Android 用 Jetpack Compose 新写 UI，两端共享业务逻辑层（API、数据库、同步、进度存储、数据模型）。

```
OneHundredVolt/          ← 现有 Git 仓库根目录
├── iosApp/              ← 现有 iOS 项目（整体移入）
├── androidApp/          ← 新建 Android 项目
└── shared/              ← KMP 共享模块（新建）
```

**新功能迭代规则**：先改 `shared/`（业务逻辑），再分别在 `iosApp/` 和 `androidApp/` 接入 UI。一个 PR 必须同时包含三处改动，防止功能漂移。

## 二、分层决策：什么进 shared，什么留平台

### ✅ 完全共享（commonMain）

| 模块 | iOS 原文件 | Kotlin 替代 |
|------|-----------|------------|
| 数据模型 | `Models/*.swift` | `@Serializable data class`，`Date` → `Long`（epoch ms） |
| API 服务 | `AfdianAPIService.swift` | Ktor Client + kotlinx.serialization |
| 本地数据库 | `DatabaseService.swift` | JSON 文件持久化，kotlinx.serialization |
| 同步服务 | `SyncService.swift` | Kotlin coroutines（`suspend fun` 对应 `async throws`） |
| 播放进度存储 | `PlaybackProgressStore.swift` | 逻辑共享，底层 KV 存储用 expect/actual |
| 错误类型 | `APIError` enum | `sealed class ApiError` |
| 协议/接口 | `Services/Protocols/*.swift` | Kotlin `interface` |

### ⚠️ expect/actual 拆分（接口共享，实现各平台）

| 功能 | expect 声明 | iOS actual | Android actual |
|------|------------|-----------|---------------|
| 安全存储 | `SecureStorage` | Keychain | EncryptedSharedPreferences |
| KV 持久化 | `KeyValueStore` | UserDefaults | SharedPreferences |
| 文件路径 | `platformPaths()` | FileManager | context.filesDir / cacheDir |
| 事件总线 | `EventBus` | NotificationCenter | SharedFlow |

### ❌ 留在平台层（平台强绑定）

| 功能 | iOS | Android |
|------|-----|---------|
| 音频引擎 | AVPlayer + AVAudioSession | Media3 ExoPlayer + MediaSessionService |
| 锁屏控制 | MPNowPlayingInfoCenter | MediaSession + Notification |
| 音频缓存 | URLSession.download | ExoPlayer 内置缓存 or 自定义 |
| WebView 登录 | WKWebView + WKHTTPCookieStore | Android WebView + CookieManager |
| 安全存储实现 | KeychainService | EncryptedSharedPreferences |
| 所有 UI | SwiftUI | Jetpack Compose |

## 七、注意事项 & 已知坑

1. **iOS 引用 shared XCFramework**：KMP 生成的 XCFramework 需要在 Xcode 里手动添加，或通过 `embedAndSignAppleFrameworkForXcode` Gradle task 自动集成。推荐用后者，在 `iosApp` 的 Xcode Build Phase 里加一个 Run Script。

2. **Android context 注入**：`SecureStorage` 和 `KeyValueStore` 的 Android actual 实现需要 `Context`。用 `lateinit var appContext: Context` 在 `Application.onCreate()` 里初始化，避免传递 context 到 shared 层。

3. **爱发电 API 的 Cookie 认证**：Android WebView 登录后，用 `CookieManager.getInstance().getCookie("afdian.com")` 提取 `auth_token`，存入 `EncryptedSharedPreferences`，逻辑与 iOS `WKHTTPCookieStore` 完全对应。

4. **音频缓存文件扩展名**：iOS `AudioCacheService` 里有处理旧格式（无扩展名）缓存的逻辑，Android 从零开始不需要兼容，直接用 Media3 `SimpleCache` 即可。

5. **`@Observable` vs `StateFlow`**：iOS 的 `@Observable` 是细粒度属性观察，Android 的 `StateFlow` 是整体状态替换。ViewModel 设计时注意 Android 端用 `data class` 封装 UI State，一次性 emit 整个状态对象。
