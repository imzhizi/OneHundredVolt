## §0 背景

2026-06-20 对整个项目（iOS / Android / shared）做了全量代码 review，发现：
- iOS 端未真正接入 KMP shared 模块，~1100 行 Swift 重复实现，导致两侧开始分叉
- 16 项 P0/P1 Bug（数据完整性、并发安全、平台 API 误用）
- iOS / Android 在清除缓存语义、WebView session 清理、MiniPlayer loading 阶段行为不一致

本计划基于用户决策：
1. **iOS 不做 OTA**
2. **Android 响度增强不做 UI 开关**（API + 状态字段保留，默认 true）
3. **接入 Shared.framework**（一次性切换，不保留兼容窗口）
4. **新建独立架构文档** `docs/architecture.md`

#### 步骤 4：类型映射速查

| Kotlin | Swift 暴露 |
|---|---|
| `data class Creator(val id: String, ...)` | `class Creator: Identifiable { var id: String; ... }` |
| `Long`（epoch ms） | `Int64`（不是 `Int`！iOS 现有用 `Int` 需全量替换） |
| `MutableStateFlow<List<X>>` | Swift 端通过 `.value` 取当前值；订阅用 `for await item in flow` |
| `suspend fun foo()` | Swift `async func foo() throws -> T` |
| `sealed class ApiError` | Swift `enum ApiError: Error` + case associated values |
| `Date` | `Date`（Foundation）— 自动桥接 |
| `URL` | `URL`（Foundation）— 自动桥接 |
| `@Transient var audioUrl: String?` | JSON 序列化时**不**写入；Swift 端可见 `var audioUrl: String?` |

**坑点**：
1. Kotlin `Long` → Swift `Int64`，iOS 现有 Swift 用 `Int`，迁移后所有 `creator.id` 等需改类型
2. `kotlinx.coroutines.flow.StateFlow` 暴露给 Swift 后，订阅需要 `Task { for await v in flow { ... } }`
3. 401 → iOS 端通过 `NotificationCenter.post(.tokenExpired)` 实现，Kotlin 端只能抛 `ApiError.HttpError(401)`；需 Swift 适配层 catch 后 post Notification
4. `WKWebsiteDataStore` cleanup 是 iOS 专属，shared 加 `WebSessionCleaner` expect/actual

#### 步骤 5：适配层代码骨架

```swift
// iosApp/OneHundredVolt/Adapters/SharedErrorAdapter.swift
import Shared

@MainActor
final class SharedErrorAdapter {
    static let shared = SharedErrorAdapter()
    private var task: Task<Void, Never>?

    func start() {
        // 监听 shared 模块内部错误流
        // 由于 Kotlin 不能直接 post iOS Notification，
        // 采用主动轮询 Shared.DatabaseService.errorEvents StateFlow
        task = Task { @MainActor in
            for await event in Shared.DatabaseService.shared.errorEvents {
                switch event {
                case .tokenExpired:
                    NotificationCenter.default.post(name: .tokenExpired, object: nil)
                case .syncFailed(let message):
                    NotificationCenter.default.post(name: .syncFailed, object: message)
                case .none:
                    break
                }
            }
        }
    }

    func stop() {
        task?.cancel()
    }
}
```

## 附录 B：深度方案 — shared DatabaseService 原子写入 + 线程安全

### B.1 现状问题

```kotlin
// 当前实现的关键缺陷
private var pendingSave = false  // ❌ 非线程安全：读改写无锁

private fun scheduleSave() {
    if (pendingSave) return
    pendingSave = true
    ioScope.launch {
        delay(100)
        flushToDisk()
    }
}

private fun flushToDisk() {
    pendingSave = false  // ❌ 在读快照之前重置
    val snapshot = DbSnapshot(...)  // ⚠️ 新 mutation 可能在此之间发生
    file.writeText(content)  // ❌ 非原子写
}
```

并发场景下的具体表现：
1. 线程 A `scheduleSave()` → `pendingSave == false` → 设为 `true` → 调度
2. 线程 B `scheduleSave()` → `pendingSave == true` → return（OK）
3. 但线程 A 还没执行 `pendingSave = true` 的瞬间，线程 B 也读到 false → 两次调度 → 两次写

### B.2 改进方案

#### B.2.1 防抖原子化

```kotlin
import java.util.concurrent.atomic.AtomicBoolean

private val pendingSave = AtomicBoolean(false)
private val savingInProgress = AtomicBoolean(false)

private fun scheduleSave() {
    // 已有 pending（100ms 防抖窗口内）→ 不再调度
    if (pendingSave.get()) return
    pendingSave.set(true)
    ioScope.launch {
        delay(100)
        savingInProgress.set(true)
        try {
            flushToDisk()
        } finally {
            savingInProgress.set(false)
            pendingSave.set(false)
        }
    }
}

private fun flushToDisk() {
    val snapshot = DbSnapshot(
        creators = _creators.value,
        albums = _albums.value,
        audioItems = _audioItems.value
    )
    try {
        val data = json.encodeToString(snapshot)
        writeFileAtomic(dbFilePath, data)
    } catch (e: Exception) {
        println("DatabaseService.flushToDisk failed: $e")
    }
}
```

#### B.2.2 原子写入

```kotlin
private fun writeFileAtomic(path: String, content: String) {
    val target = File(path)
    target.parentFile?.mkdirs()
    val tmp = File("${path}.tmp.${ProcessHandle.current().pid()}.${System.nanoTime()}")
    try {
        // 先同步写入临时文件，fsync 确保落盘
        java.io.FileOutputStream(tmp).use { fos ->
            fos.write(content.toByteArray(Charsets.UTF_8))
            fos.fd.sync()
        }
        // POSIX rename 原子；Windows 上 renameTo 失败需 fallback
        if (!tmp.renameTo(target)) {
            target.delete()
            if (!tmp.renameTo(target)) {
                tmp.copyTo(target, overwrite = true)
                tmp.delete()
            }
        }
    } catch (e: Exception) {
        tmp.delete()
        throw e
    }
}
```

#### B.2.3 加载时的损坏恢复

```kotlin
private fun load() {
    try {
        val data = readFile(dbFilePath) ?: return
        val snapshot = json.decodeFromString<DbSnapshot>(data)
        _creators.value = snapshot.creators
        _albums.value = snapshot.albums
        _audioItems.value = snapshot.audioItems
    } catch (e: Exception) {
        // JSON 损坏：把坏文件改名保留，用户后续可手动恢复
        try {
            val corrupt = File("${dbFilePath}.corrupt.${System.currentTimeMillis()}")
            File(dbFilePath).renameTo(corrupt)
        } catch (_: Exception) {}
    }
    cleanupTempFiles()
}

private fun cleanupTempFiles() {
    val dir = File(dbFilePath).parentFile ?: return
    dir.listFiles { f -> f.name.startsWith("${File(dbFilePath).name}.tmp.") }
        ?.forEach { it.delete() }
}
```

## 附录 C：深度方案 — iOS AudioPlayerService @MainActor 重写

### C.1 现状问题

```swift
@Observable
final class AudioPlayerService: @unchecked Sendable {  // ❌ 关闭编译器检查
    // 任何线程都能调用，运行时无保护
```

### C.2 改造方案

```swift
@MainActor
@Observable
final class AudioPlayerService {
    static let shared = AudioPlayerService()  // 首次访问时初始化（main thread）

    // 所有属性自动 MainActor-isolated
    private(set) var currentItem: AudioItem?
    private(set) var playlist: [AudioItem] = []
    private(set) var isPlaying: Bool = false
    private(set) var isLoading: Bool = false
    private(set) var currentTime: TimeInterval = 0
    private(set) var duration: TimeInterval = 0
    private(set) var loadError: String?
    private(set) var playbackRate: Float = 1.0
    private(set) var sleepRemainingSeconds: Int = 0
    // ...
}
```

### C.3 关键迁移点

| 原代码位置 | 问题 | 改法 |
|---|---|---|
| `init`（line 25） | 默认在 main 初始化（OK） | `@MainActor` 标注 init |
| KVO 回调（line 359） | `Task { @MainActor in ... }` 包裹（line 362） | KVO callback 本就在 main run loop 触发；直接同步调用即可 |
| `AVPlayerItemDidPlayToEndTime` notification（line 412） | `addObserver(selector:)` callback 在 main | 改为 `NotificationCenter.default.addObserver(forName:..., object:..., queue: .main) { [weak self] _ in Task { @MainActor in self?.handlePlaybackFinished() } }` |
| `DispatchQueue.main.asyncAfter` 睡眠定时器（line 293） | OK，已在 main | 保留 |
| `persistPlaylist`（line 89） | 调 `UserDefaults.set`，同步 | 保留同步；UserDefaults 本身线程安全 |
| Singleton 访问 `private let player = AudioPlayerService.shared` | SwiftUI view 默认 MainActor，OK | 保留 |

### C.4 @MainActor 带来的限制

| 调用方 | 影响 |
|---|---|
| SwiftUI views（HomeView/PlayerView/MiniPlayerView 等） | 默认 MainActor，**无影响** |
| Tests 中通过 `Task.detached` 调用 | 编译错；改用 `await MainActor.run { ... }` |
| `SyncService.sync` 在 background 调 `audioPlayer.appendToPlaylist` | 编译错；改为 `await MainActor.run { AudioPlayerService.shared.appendToPlaylist(...) }` |
| KVO callback（ObjC selector） | 改为 `Task { @MainActor in self?.handler() }` |

### C.5 风险评估

| 风险 | 概率 | 缓解 |
|---|---|---|
| 某些被调函数意外 background 调用导致编译错 | 中 | 一次性全部修复，编译报错会精确指出 |
| 现有 `@unchecked Sendable` 隐式假设被打破 | 低 | 编译错暴露问题，正是收益 |
| 第三方 SDK（如 AVPlayer 的 callback）非 MainActor | 低 | AVPlayer 所有 callback 都在 main |
